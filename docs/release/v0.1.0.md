# v0.1.0 release note (draft)

**Draft. Not tagged, not published.**

## OTA kit 0.1.0

First release of a small Zephyr module, host scripts and a hardware test suite for firmware updates with MCUboot: signed images, a test boot that has to pass a health check, and automatic rollback.

### What you get

- A Zephyr module you turn on with a snippet: `west build --sysbuild -S ota-kit ...`
- One call in your application: `ota_kit_set_health_check(my_check)`.
- Updates over UART, Bluetooth LE or Wi-Fi (SMP over UDP) with `scripts/ota_update.py`.
- A watchdog that the bootloader starts and the application takes over, so that an image that hangs, also before `main()`, is reset and reverted.
- `scripts/ota_doctor.py`, which reads a finished build and reports OTA configuration mistakes before you flash.
- A failure suite that runs on the board and records the bootloader line that proves each result.

### Tested on

| Board | Transport | Result |
|---|---|---|
| ST B-L475E-IOT01A (`disco_l475_iot1`) | UART | Tested. Failure suite 11 of 11. 20 of 20 updates, 18.4 s mean. 60 power cuts, no board lost |
| ST B-L475E-IOT01A | Bluetooth LE | Tested. Failure suite as expected, twice. 25 of 25 updates, 54 to 56 s mean |
| ST B-L475E-IOT01A | Wi-Fi, connected UDP socket through a relay script | Partial. Failure suite 10 of 10 on the second pass. 3 of 10 update runs in the second series stopped during the upload, cause not found |
| ESP32 WROOM-32 (`esp32_devkitc`) | Wi-Fi, SMP over UDP | Supported. Failure suite clean in four passes. 30 of 30 updates, 31 s median for a 682 K image, and 5 of 5 on a build with the HAL patch |
| ESP32 WROOM-32 | UART | Partial. One unanswered request in about 100 uploads, cause not found |
| ESP32 WROOM-32 | Bluetooth LE | Not tested. Two updates worked, no suite |

Zephyr `133c2eb7d3cb` (4.4 development tree), MCUboot `7ad67106`, hal_espressif `5e3b702250`. One board of each kind. Nothing else has run on hardware.

### Read this first

- **Demonstration project, two boards, one maintainer.** Not a product, not certified.
- **The debug port is open** in this setup. Anyone with a probe or the USB cable can read keys and replace the bootloader.
- **Power loss was tested only as a clean cut** with one small image on the STM32: 60 cuts, no board lost. Brown out and large images are open.
- **The device reboots for an update whenever the host asks.** There is no safe state check.
- **SMP over UART and over UDP has no authentication.** Anyone on the port or on the network can upload, erase and reset. They cannot make an unsigned image boot.
- **ESP32 builds need a patch to the Espressif HAL** to be safe from an image that aborts before `main()`. It is two lines from an open upstream issue, carried in `zephyr/patches.yml`, and has to be applied after every `west update`.

The full list is in the changelog under "Known limits", in `docs/REFERENCE.md` and in `docs/HAZARDS.md`.
